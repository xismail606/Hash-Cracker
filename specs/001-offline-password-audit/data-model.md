# Data Model: Hash Cracker

## Hash Assessment

| Field | Type | Rules |
|---|---|---|
| submitted hash | string | Trim outer whitespace; reject empty and non-hex values for the supported v1 formats |
| normalized hash | lowercase hex string | Validate against the selected algorithm's expected digest length |
| compatible algorithms | list | MD5 and NTLM are both candidates for 32 hex characters; SHA-256 is a candidate for 64 hex characters |
| selected algorithm | optional name | Required when more than one supported format matches the input shape |

## Audit Request

| Field | Type | Rules |
|---|---|---|
| target hash | string | Must be valid for the selected algorithm |
| algorithm | name | One of `md5`, `sha256`, `ntlm`; explicit selection for ambiguous formats |
| mode | enum | `dictionary` or `brute-force` |
| wordlist path | local path | Required for dictionary mode; web upload limit 256 MiB |
| charset | string or preset | Required for brute-force mode; non-empty and unique characters |
| minimum length | integer | Required for brute-force mode; positive and no greater than maximum length |
| maximum length | integer | Required for brute-force mode; must be compatible with the configured candidate budget |
| candidate budget | integer | Default 1,000,000; hard maximum 10,000,000 candidates per run |
| workers | integer | Default 4; accepted range 1 through 8 |
| result warning acknowledged | boolean | Must be acknowledged before a run that can persist a successful plaintext/hash pair |

## Candidate

A candidate is either one line read from a finite local wordlist or one string generated by brute-force mode.

| Field | Type | Rules |
|---|---|---|
| value | string | Never written into audit history unless it is a successful match |
| source mode | enum | `dictionary` or `brute-force` |
| candidate index | integer | Monotonically increasing per run for attempts and progress reporting |

Dictionary entries preserve duplicates and whitespace other than the line terminator. Brute-force candidate strings are generated deterministically from the selected alphabet and length bounds and stop at the candidate budget.

## Audit Run

| Field | Type | Rules |
|---|---|---|
| run ID | integer or opaque ID | Unique within local history/job tracking |
| started at | UTC timestamp | Set when candidate processing begins |
| completed at | UTC timestamp | Set for terminal states when available |
| target hash | string | Persisted locally for audit reporting; not transmitted externally |
| algorithm | enum | `md5`, `sha256`, or `ntlm` |
| mode | enum | `dictionary` or `brute-force` |
| status | enum | `match`, `no_match`, `invalid_input`, `cancelled`, `budget_exhausted`, `interrupted`, `storage_error` |
| attempts | integer | Number of candidates actually evaluated |
| elapsed milliseconds | integer | Non-negative duration |
| worker count | integer | Effective count between 1 and 8 |
| matched plaintext | optional string | Present only for a successful match; stored locally because the assignment requires successful plaintext/hash pairs |

## Audit History Record

A local SQLite record for every completed or interrupted audit. Successful records contain the plaintext/hash pair, algorithm, mode, attempts, elapsed time, worker count, and timestamp. Non-matching records contain the target hash and run metadata without a plaintext value.

## Dashboard Job

| Field | Type | Rules |
|---|---|---|
| job ID | opaque identifier | Does not expose filesystem paths |
| state | enum | `validating`, `queued`, `running`, or a terminal Audit Run state |
| progress | counters | Attempts completed, configured budget, and current phase; never expose candidate values |
| temporary upload path | local path | Only used for dictionary mode; delete after completion, cancellation, validation failure, or shutdown |
| result | Audit Run summary | Includes recovered plaintext on match, consistent with the assignment; displays a sensitivity warning |

## State Transitions

An audit follows `created` → `validating` → `running` → one terminal state: `match`, `no_match`, `budget_exhausted`, `cancelled`, `interrupted`, or `storage_error`. Invalid inputs terminate before candidate work. A dashboard job removes its temporary upload when it enters a terminal state.

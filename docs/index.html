✦ Features

Everything a local audit needs

Both the CLI and the dashboard call the same Python audit engine — bounded multiprocessing, explicit candidate budgets, and structured history records.

One engine, two interfaces

A bounded process pool spreads candidates across 1–8 CPU workers with live progress, attempts, elapsed time and ETA. Runs stop on a match, a cancellation, or the candidate budget — default 1M, hard max 10M. Pause and resume checkpoint the exact wordlist position, so nothing is skipped or re-hashed.

Structure-based identification

Assesses a hash by length and character shape, lists compatible algorithms, and requires an explicit pick when a shape is ambiguous — MD5 / NTLM / MD4 never get guessed.

Dictionary + mutation rules

Streams a local wordlist against the target with optional rule presets — leetspeak, capitalization, append_digits_0_99, year appends, or all combined.

Bounded brute-force

Explicit charset and length range, stopping at a budget. No runaway searches, ever.

Hashlist mode

Many targets, one pass — each candidate is hashed once per algorithm and probed against every target.

Pause / resume

Dashboard jobs checkpoint their offset and continue later with validated byte positions.

Benchmark

Real per-algorithm candidates/second on your machine, so budgets get sized honestly.

History & export

SQLite records for every run, CSV/JSON export, optional plaintext encryption at rest.

Local dashboard

Astro + React + Tailwind UI on a loopback-only Flask API — chips, live progress, per-target tables.

✦ How it works

Four steps, fully local

01

Submit the target

Paste a hash in the CLI or dashboard. The identifier checks its shape and lists compatible algorithms.

02

Pick the algorithm

Ambiguous shapes require an explicit selection so results are never guessed.

03

Choose a mode

Dictionary with optional rules, bounded brute-force, or a hashlist — then set workers and budget.

04

Get results

The engine stops on a match, budget, or cancellation; the run is recorded to local SQLite for export.

✦ Installation

One command to set up

Requires Python 3.11+, Node.js/npm, and a modern browser. The setup script installs Python and Node dependencies, builds the dashboard, and runs the test suite. It is idempotent — safe to re-run.

Windows — PowerShell 
# clone the repository
git clone https://github.com/xismail606/hash-cracker.git
cd hash-cracker

# one-command setup (deps + dashboard build + tests)
powershell -ExecutionPolicy Bypass -File .\setup.ps1

# start the dashboard
.\serve.ps1
Linux / macOS — bash 
# clone the repository
git clone https://github.com/xismail606/hash-cracker.git
cd hash-cracker

# one-command setup (deps + dashboard build + tests)
./setup.sh

# start the dashboard
./serve.sh
Open the dashboard 
# binds to 127.0.0.1 — nothing leaves your machine
python -m password_audit serve
# → open http://127.0.0.1:8765
✦ Usage

The CLI in three commands

The same engine powers both interfaces. Exit codes: 0 success, 1 invalid input, 2 cancelled, 3 storage failure.

Identify a hash 
python -m password_audit identify 8743b52063cd84097a65d1633f5c74f5
# → 32-hex shapes are ambiguous: MD5 / NTLM / MD4 — choose explicitly
Dictionary audit with mutation rules 
python -m password_audit audit 8743b52063cd84097a65d1633f5c74f5 \
    --algorithm md5 --mode dictionary --wordlist words.txt \
    --rules leetspeak --workers 4
Bounded brute-force + benchmark 
# measure real per-algorithm throughput first
python -m password_audit benchmark --seconds 1

python -m password_audit audit 8743b52063cd84097a65d1633f5c74f5 \
    --algorithm md5 --mode brute-force \
    --charset lower,digits --min-length 1 --max-length 4 \
    --max-candidates 10000 --workers 4
History & export 
python -m password_audit history
python -m password_audit export report.csv --format csv
✦ Safety & limits

Authorized use only, by design

Local-only by default

The web app binds to 127.0.0.1, all input processing stays local, and state-changing requests use same-origin CSRF protection. No logins, no remote targets, no external transfers.

Explicit consent before storage

Successful plaintext/hash pairs are stored locally — the operator acknowledges a sensitive-data warning first, or passes --no-store-plaintext to withhold it.

Hard limits on every run

Brute-force requires an explicit charset and length range; budgets default to 1M (max 10M) candidates; workers cap at 8; dashboard wordlist uploads cap at 256 MiB.

Encryption at rest

Optionally encrypt stored plaintexts with a passphrase-derived Fernet key; history shows <encrypted> until unlocked in the CLI or dashboard.
